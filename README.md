# بوت تيليجرام — نسخة جاهزة لـ GitHub وRailway

هذه الحزمة مُعدة للرفع إلى GitHub ثم النشر على Railway. يوفّر ملف `railway.toml` أمر تشغيل صريحًا، ومسار فحص صحي، وسياسة إعادة تشغيل. يدعم Railway حفظ هذه الإعدادات في ملف مرفق مع الكود، بما في ذلك أمر التشغيل ومسار الفحص الصحي وسياسة إعادة التشغيل.[1]

> **تنبيه أمني مهم:** كان رمز البوت وبيانات واجهة تيليجرام ظاهرين في الملف الأصلي. اعتبرها مكشوفة: أنشئ **رمز بوت جديدًا** من BotFather قبل النشر، ولا ترفع ملف `.env` أو أي ملف جلسة أو قاعدة بيانات إلى GitHub.

## محتويات الحزمة

| الملف | الغرض |
|---|---|
| `bot.py` | البوت بعد إصلاح الأزرار، الحالات، المهام الخلفية، وفحص الصحة. |
| `requirements.txt` | تبعيات بايثون التي يثبتها Railway تلقائيًا. |
| `railway.toml` | إعداد البناء والتشغيل وفحص الصحة وإعادة التشغيل. |
| `.env.example` | نموذج لمتغيرات البيئة فقط؛ ليس ملف أسرار حقيقيًا. |
| `.gitignore` | يمنع رفع الأسرار والجلسات وقاعدة البيانات. |
| `test_bot.py` | اختبار محلي لا يتصل بتيليجرام. |

## 1. رفع المشروع إلى GitHub

فك ضغط الحزمة، ثم ارفع **محتويات** مجلد `telegram_bot_repaired` إلى مستودع GitHub جديد. لا ترفع ملف ZIP نفسه داخل المستودع. تأكد قبل الرفع من أن ملفات `.env` و`database/` و`bot_session*` غير موجودة في قائمة الملفات، إذ إن `.gitignore` يستبعدها تلقائيًا.

إذا كنت تستخدم Git محليًا، نفّذ الأوامر التالية من داخل مجلد المشروع بعد إنشاء مستودع فارغ على GitHub واستبدال الرابط برابطك:

```bash
git init
git add .
git commit -m "Prepare Telegram bot for Railway"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

## 2. إنشاء خدمة Railway

أنشئ مشروعًا جديدًا في Railway واختر النشر من مستودع GitHub، ثم حدّد المستودع والفرع `main`. سيقرأ Railway ملف `railway.toml` من جذر المشروع؛ لذلك لا تحتاج إلى إدخال أمر تشغيل يدويًا. الإعداد المحدد هو `python bot.py`، ومسار فحص الصحة هو `/`، وسيعيد Railway تشغيل العملية عند خروجها بخطأ.

## 3. إنشاء تخزين دائم

ينبغي إنشاء **Volume** في خدمة Railway وربطه بمسار `/data`. بعد ذلك أضف المتغير `BOT_DATA_DIR` بالقيمة `/data`. هذه الخطوة ضرورية لأن البوت يحفظ قاعدة البيانات وجلسة البوت في هذا المسار؛ من دون تخزين دائم قد تُفقد الحسابات والإعدادات بعد إعادة النشر أو إعادة التشغيل.

## 4. متغيرات البيئة في Railway

من تبويب **Variables** في خدمة Railway، أضف القيم التالية. لا تضفها إلى الكود أو GitHub.

| المتغير | القيمة المطلوبة | ملاحظة |
|---|---|---|
| `TELEGRAM_API_ID` | رقم `api_id` لتطبيق تيليجرام | قيمة رقمية فقط. |
| `TELEGRAM_API_HASH` | `api_hash` لتطبيق تيليجرام | تعامل معه كسر. |
| `TELEGRAM_BOT_TOKEN` | رمز البوت الجديد من BotFather | لا تستخدم الرمز المكشوف سابقًا. |
| `TELEGRAM_ADMIN_ID` | معرّف المشرف الرقمي | ليس اسم المستخدم. |
| `REQUIRED_CHANNEL` | اسم القناة، مثل `enmotaz` | اختياري؛ من دون `@`. اتركه فارغًا لتعطيل الشرط. |
| `BOT_DATA_DIR` | `/data` | مطلوب عند استخدام Volume. |
| `MIN_POST_INTERVAL` | `60` مثلًا | اختياري؛ الحد الأدنى للنشر التلقائي بالثواني. |
| `MAX_GROUPS_PER_CYCLE` | `15` مثلًا | اختياري؛ حد المجموعات في كل دورة نشر. |
| `MAX_GROUPS_TURBO` | `10` مثلًا | اختياري؛ حد النشر السريع للحساب. |

لا تُضف `PORT` يدويًا في Railway. يقرأ التطبيق المنفذ الذي توفره المنصة تلقائيًا، ويستمع على العنوان `0.0.0.0`؛ أما القيمة الموجودة في `.env.example` فهي للاستخدام المحلي فقط.

## 5. التحقق بعد النشر

بعد اكتمال النشر، افتح **Deploy Logs** وتحقق من ظهور رسالة أن البوت يعمل ومن عدم وجود أخطاء إعداد. سيُجيب المسار `/` بحالة JSON تفيد بأن الخدمة حية. جرّب بعدها في تيليجرام: `/start`، ثم إدارة الأرقام، ثم زر محرك النشر، وأخيرًا اختبار زر الرجوع والضغط المتكرر على أي زر. إذا كان `REQUIRED_CHANNEL` مفعلًا، امنح البوت الصلاحية المناسبة في القناة كي يتمكن من التحقق من العضوية.

## اختبار محلي اختياري

تستطيع التحقق من سلامة الكود قبل الرفع دون مفاتيح تيليجرام حقيقية:

```bash
python3 -m pip install -r requirements.txt
python3 -m py_compile bot.py test_bot.py
python3 test_bot.py
```

## نقاط إصلاح أساسية

| المشكلة السابقة | ما تم إصلاحه |
|---|---|
| `MessageNotModifiedError` عند ضغط الزر نفسه | استُخدمت دالة تعديل آمنة تعترف بأن المحتوى لم يتغير بدل إسقاط معالج الزر. |
| أزرار النشر العادي والمجدول غير مكتملة | أصبحت لها تدفقات كاملة: رسالة ثم حساب ثم تنفيذ أو جدولة. |
| معالجات رسائل متداخلة | استُبدلت بحالة إدخال واحدة معزولة لكل مستخدم، ما يمنع تداخل الرموز والرسائل والإعدادات. |
| الرد التلقائي شكلي فقط | أصبح له تشغيل وإيقاف ونص مستقل لكل حساب ومهمة خلفية. |
| فقدان البيانات في الاستضافة | أصبح المسار قابلًا للربط بوحدة تخزين دائمة عبر `BOT_DATA_DIR`. |
| تحذير Flask التنموي في السجل | استُبدل خادم التطوير بخادم WSGI خفيف لفحص الصحة. |
